## 📖 Documentation Standards

### File Naming
- Use UPPERCASE for root-level docs (README.md, CLAUDE.md)
- Use descriptive names (TESTING_GUIDE.md not test.md)
- Use underscores for multi-word (SYSTEM_ARCHITECTURE.md)

### Content Structure
All documentation follows this structure:
1. Title and description
2. Table of contents (for long docs)
3. Main content with clear sections
4. Examples and code snippets
5. Related links and references

### Code Examples
- Always include working code examples
- Show both command and expected output
- Include error handling examples

### Maintenance
- Update docs with code changes
- Keep examples current
- Add new sections as features are added
- Review quarterly for accuracy
